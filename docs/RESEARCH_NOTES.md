# 影响本原型的调研证据

核对日期：2026-10-21。只保留影响产品设计的结论。公开来源是研究材料；演示中的 DEMO-MKT v1 是虚构公司政策，不是这些来源的法律解释或完整转写。

| 证据 | 设计后果 |
|---|---|
| [MAS FSG-03 官方指南](https://www.mas.gov.sg/-/media/mas/regulations-and-financial-stability/regulations-guidance-and-licensing/financial-advisers/guidelines/guidelines-on-standards-of-conduct-for-digital-advertising-activities.pdf) 第 1.7 段写明 2026-03-25 生效；指南涉及数字广告及相关机构的行为要求。 | 保存渠道、发布关系及所需材料；不从公司总部位置推定全部客户适用同一法域。 |
| [MAS 良好实践材料](https://www.mas.gov.sg/-/media/mas/publications/information-papers/information-paper-on-good-practices-of-market-conduct-controls-in-the-financial-advisory-industry.pdf) 列举审批、截图留存和抽查等实践。 | 区分规则来源与性质；不把良好实践示例改写为对所有机构都适用的独立强制法条。 |
| [ASAS 附件 B](https://asas.org.sg/Portals/0/Annex%20B%20-%20Guidance%20notes%20for%20Interactive%20Marketing%20Communication%20and%20Social%20Media.pdf) 区分图片、视频和音频等披露形式。 | 文字稿不能证明最终图片的展示效果。缺最终图片时输出所需材料；视频规则须先检查是否适用。 |
| [Harvey Workflow 示例](https://www.harvey.ai/blog/getting-started-with-workflow-builder-5-workflows-we-recommend) 展示输入引用、多个 prompt 以及前后步骤输出关系；[Agent Builder](https://www.harvey.ai/blog/introducing-agent-builder) 介绍可复用流程和人工检查点。 | Skill 保存单项能力，Workflow 明确传值；中途人工审批作为下一阶段功能，首版不宣称已实现。 |
| [Spellbook Playbook 最佳实践](https://help.spellbook.legal/en/articles/11327960-playbooks-best-practices) 强调具体规则和样例测试。 | 用户配置明确的任务、输入和输出；用模拟材料逐项检查，而非仅确认 JSON 可解析。 |

以上同类产品结论来自一手公开资料阅读，没有实测 Harvey 或 Spellbook 账号，也没有评价其准确率。以下另列 AltaLex 的真实 UI 试用和静态脚本观察，二者证明的范围不同。

## 真实 UI 试用：Negotiation Playbook

2026-10-21，在获授权的 AltaLex 测试账号中上传了一份虚构采购政策，模拟买方采购营销工作流 SaaS。输入要求只依据政策 P1–P5，列明政策 ID、首选立场、允许的退让、业务理由、缺失资料和批准人；没有退让方案时应写未规定。结果页显示流程完成，并呈现了谈判手册。这个结果证明本次从输入到生成报告的链路可用；检查范围为结果页可见部分，没有对报告全文做专业法律验证。

| 核对项 | 输入与可见输出的比较 | 业务含义 |
|---|---|---|
| 保留批准要求 | P1 规定责任上限首选 12 个月费用，退让至 6 个月须经法务批准；可见报告保留了这个批准要求。P2 对数据用途变更的书面法务批准也仍可见。 | 把批准人和条件写进结果有帮助，但不能仅凭报告完成认定所有公司边界均被正确保留。 |
| 自行补充法域与策略 | 输入没有指定法域或谈判强度；报告推断美国或英格兰与威尔士，并选择强势谈判模式。报告虽标为推断，仍未经过用户确认。 | 法域、商业紧迫程度和可接受姿态应成为待确认输入，不能用行业惯例代替客户决定。 |
| 新增退让条件 | P1 的 6 个月退让只要求法务批准；报告又加上加强数据泄露赔偿或服务抵扣的条件。P2 没有预设匿名数据使用的退让，报告却提出附带法务批准和匿名化条件的方案。 | 这些可以是模型建议，不能直接标成公司已批准的政策。即使建议更保守，也需要明确来源并由人确认。 |

因此应明确区分三类内容：**公司政策**是用户提供并确认的要求；**模型建议**是基于任务生成、尚未纳入政策的备选方案；**待确认事项**是缺少法域、商业背景、授权或证据的信息。原文政策、建议和未知事项混在一张完整表格里，容易让“写得像规则”被误认为“已有依据”。本次试用没有检验其他文档、其他权限或重复运行的一致性，不能据一次结果估计整体准确率。

## 尽调：将静态路径与真实 UI 试用对应

先对浏览器已经收到的发布脚本进行 REA 定向检查，观察到“收集交易背景 → 请求生成审阅清单 → 用户编辑或勾选 → 带选定清单和文件启动审查”的路径。该静态分析只选择 42 个库存文件中的 1 个，语义图存在截断；它用于定位交互与数据组织，没有取得后端源码，也不能证明模型调用数量或运行质量。

随后于本地日期 2026-10-21 实际跑完一次尽调 UI，使用一份明确标注虚构的简短 SaaS 协议：

| 环节 | 本次操作与可见结果 | 业务含义 |
|---|---|---|
| 生成清单 | 背景要求只审阅续期、转让与控制权变更、数据迁出 3 项，首轮仍生成 28 项。 | 输入中的范围限制未直接约束候选清单；用户需要看到并确认实际审阅范围。 |
| 修改与选择 | 对话要求仅保留上述 3 项后，清单成功缩至 3 项；取消全选时，Next Step 按钮实测禁用。 | 静态代码中的编辑与选择，在本次账号里形成了可操作的中间确认阶段。 |
| 执行 | 全选这 3 项，上传虚构 DOCX 并运行；结果页显示流程完成。 | 本次链路已从清单走到生成结果，超出了只观察启动响应的证据范围。 |
| 核查结果 | Findings 表保留 3 项，并分别给出 Clause 2、3、4 引用，与模拟文档的相关条款对应。 | 用户有具体原文定位可核查；引用存在不等于报告的法律判断已验证正确。 |
| 下载 | 点击 Download All 后出现 SessionExpired，未取得下载文件。 | 已生成可见报告，但本次不能记作导出成功。 |

报告也暴露出需要进一步验证的范围和决定权问题：三项 Findings 之外，叙述报告新增了第 2.4 节“标准合同保护缺失”，并加入市场标准、过渡期限和后续行动期限等建议；还出现了附带条件的“Transaction can proceed”表述。这些是本次可见输出中的模型补充，不能自动当成用户选定范围、已确认市场依据或交易决定。本次没有对这些建议作法律准确性断言。产品应把所选检查的结果、范围外补充建议与需人决定事项分开，尤其不应由一份自动报告替客户作交易批准。

报告日期显示 22 October 2026，实际本地操作日期为 2026-10-21；原因未查明，不据此推断时区或系统故障。[本次结果页](https://app.alta-lex.ai/workflows/detail/38059065-2774-4922-b35a-652b0f8be2e0) 需要相应账号权限，交付原型不依赖该链接才能运行。

证据分工为：当次操作记录与清单／结果截图支持交互过程，结果页可见文字支持报告内容，静态 REA 路径解释其前端组织。本轮末的 REA 被动快照仅反映捕获时的会话切片，不能单独证明此前的清单编辑、按钮状态或上传过程。一次真实成功也不证明其他材料、权限或重复运行均一致。

两类证据共同修正了一个影响方案的推断：**前端的 steps 是用户工作阶段，不等于模型调用次数或可复用 Skill 数。** 上传文件、填写背景和确认清单都可能各占一个界面阶段。对自助产品，更具体的需求是“生成中间产物 → 人选择或修改 → 继续处理”；是否必须支持暂停确认，应由首个客户场景决定。

## 对本原型的具体约束

- 第二步保留原始文案、背景、所选规则和第一步完整结果，用实际执行记录核对传值，避免只依据摘要或页面步骤数判断。
- 输出要能追到原文和选定规则；缺证据、规则不适用与适用待确认分开表达。模型新增的退让条件、范围外观察或商业判断应单列为建议，不自动变成政策或批准决定。
- 当前首版顺序执行，展示结果供人工核查；尚未实现流程中途暂停、确认或批准。尽调的静态路径与真实试用支持将该交互列为后续优先项，不能将它算作首版已完成能力。
- 原型执行器和界面独立实现。交付包不包含 AltaLex 生产资源、调试会话、登录凭据或用户资料，也不依赖本机私有证据目录才能运行。

尚未验证：AltaLex 实际客户角色、业务量、可接受错误、首个上线法域、真实数据要求，以及本原型能否减少审阅时间或返工。上述问题作为产品假设保留。真实 UI 试用回答了“本次操作能否完成、这份材料生成了什么”，静态追踪回答了“发布脚本怎样组织一条业务路径”；它们都不能替代真实用户验证。

## 本轮补测：资料问答已经存在，自助方法仍需单独验证

2026-10-21 在用户完成登录后的授权测试账号内，分别走完两条资料流；均仅上传本任务已制作的虚构样例。

- **Library：** 新建“DEMO — fictional negotiation policies — 21 Oct”，选择 General Legal Documents，上传虚构采购政策。编译完成后显示摘要。限定只依据该资料查询 P1，回答保留了责任上限首选 12 个月费用、退让 6 个月且需要法务批准；点击引用后打开原文第 1 页并核对。这一例没有把退让当成已获批准。
- **Project：** 新建“DEMO — SaaS purchase review — 21 Oct”，上传虚构 SaaS 合同并完成摘要。限定查询 Clause 4，回答引用 15 天终止后删除期，指出未约定导出格式、协助承诺及提前导出窗口，并列出给合同负责人的问题；点击引用显示原文第 1 页。回答还提出了触发时间和备份保留问题，这些属于进一步澄清建议，不能当成合同已有义务；本次没有出现交易可以进行的结论。

两例均完成 UI 创建、上传、编译、问答与原文定位；未验证跨会话持续性、真实权限、补件后版本关联或跨工作流复用。研究档案保留 `library_policy_query_visible.txt`、`library_policy_query.png`、`project_contract_query_visible.txt`、`project_contract_query.png`，不随原型包分发账号截图。

REA 对这两个页面入口与共用文件处理脚本分别作定向静态分析。共用脚本显示上传时 auto_compile=false，成功文件随后进入编译任务；Project 分支带 project_id，文件处理的可选 skill 同时作为编译的 schema_name。该字段与文件处理有关，不能凭同名断言它已提供考题中的自建任务能力。分析只选择 42 个库存脚本中的局部，0 个解析失败不代表完整理解后端。实时 CDP 在成功列出目标后连接失败，本次没有新的实时请求证据；以上成功操作由 Computer Use 记录。

**影响产品决定的结论：** 保存资料、问答、生成清单已有可见能力。我们应验证客户能否把自己确认过的检查方法与交付标准配置、测试、保存和用于新材料，并让使用者看清依据与未决事项。对创建者的帮助、适用范围、规则维护、改稿后的处理，应比增加模型步骤优先。具名法律人员的工作实践和 Harvey／Spellbook 对照详见[业务反思](LEGAL_WORK_REALITY.md)。
