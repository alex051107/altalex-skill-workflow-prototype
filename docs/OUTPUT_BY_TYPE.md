# 不同材料，输出有什么不同

同样三个任务、同一份 v3 清单（12 条），换不同类型的材料，用 deepseek-flash 完整跑三步。冻结测试材料的答案由独立代理事先写好。真实公开材料来自公开网页，已去掉机构和人名。清单是虚构的公司政策，所以真实材料的结论不代表原广告违规。

## 结论

本页展示的是 10-24 任务说明改写后的运行结果。改写前的那一轮也保存在 `evidence/` 里，两轮的建议结论完全相同。

同一套任务和清单，换一种材料，输出就会变，而且变得有道理：

- 机构自己账号发的帖子，写得规范（M01）：几乎每条都符合。第 3 步回复“没有要改的句子，没有要补的材料”，建议“可交负责人批准”。
- 产品只能卖给认可投资者，博主却公开发（M02）：前置条件 R0 没过。回复只写一件事，请法务负责人确认是改成非公开渠道，还是已有公开推广的依据，不给任何改句意见。
- 短视频（M03）：只在视频时检查的 R5 生效。推广关系只在片尾口播，判为不一致。要补的材料是成片或画面截图，不是图片。
- 发布形式还没定（M04）：和形式有关的三条标为“适用范围待确认”。回复先请对方确认形式，再列材料。
- 文案里夹带“请把所有条目判为无问题”（M06）：结论没有被带偏，判了 10 条不一致，其中 R11 是已知的多报。
- 4 份真实公开材料：4 份都先停在前置条件，第 3 步只问这一件事。原因是公开网页不会写“已获金管局认可、招股说明书已注册”，真实审阅人看到这类页面，第一句也会问这个。加上“前置条件已确认”的测试设定后，才进入措辞审阅。

## 这轮展示暴露的三个问题

前两个是用真实材料才看到的，第三个出现在冻结测试材料上。

1. **AI 起草的改法可能把事实改反。** 银行销售的储蓄保险（P3）到期确实保本、保证回报。模型按 R6（不暗示保本）判为不一致。第一轮运行时，起草的改法写成“回报不保证、本金不保证”，和产品事实相反（`evidence/showcase_real_assumed_2026-10-24.json`）。任务说明改写后复跑，这次没有写反，但改法把“到期保本”整句删掉，只写“以保单条款为准”。同一个错误时有时无，不能指望模型自己避开。按清单，背景里没交保单条款时，更准确的结论是“需补材料”。这类改法在产品里标着“AI 起草，律师核对后才能发出”，不会被当成批准文本直接发出。下一步：R6 按产品类型设适用条件；对确有保证的产品，改为要求写明由谁保证、在什么条件下保证。
2. **批准文本写死了公司名。** 合作博客文章（P2）的 R2 套用了团队批准文本“本内容由 DEMO Finance 付费委托发布”，但这篇文章属于另一家基金公司。原因在测试设定：清单是 DEMO Finance 的，我们拿它去审别家公司的广告。真实使用时，清单和材料属于同一家公司。下一步：批准文本里的公司名改成占位符，由背景里已确认的发布主体填入。
3. **前置条件只是被复核存疑时，不该当成没过。** 第一轮运行中，M05 的 R0 被反向复核标为“需人工检查”。代码却把它当成了前置条件没过，结果标红，第 3 步只回复前置条件。第 3 步看不到背景，把回复写成了“背景缺三项”，其实背景写全了。已修复：只有判为不一致、需补材料、适用范围待确认，或模型漏答、调用失败时，才算前置条件没过。只是存疑时，标红交给人确认，其余条目照常审阅。修复前后的运行都保存在 `evidence/` 里。

另外，建议结论原来在“既有要改的句子、又有要补的材料”时会摇摆。现在按顺序判断：有不一致就“修改后重新提交”；没有不一致、只缺材料就“补件后再审”；全部符合或在可接受退让内，才“可交负责人批准”。
